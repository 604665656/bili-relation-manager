# B站关注管理台 · Electron 版

多账号并行的 B 站关注关系管理工具，桌面 EXE，数据全部本地存储。

## 功能

**基础**
- 扫码登录，多账号并存，**同时并行执行**，各自独立限速
- 清理单向关注 / 回粉互粉 / 两者都做
- 演练模式、白名单、跳过认证账号与特别关注、CSV 导出

**统计与循环**
1. **关注数 / 粉丝数实时统计** — 每轮任务自动刷新，另有独立定时刷新（默认 5 分钟一次），账号卡片直接显示数值与增减量（`+3` / `-2`）
2. **自动循环** — 一轮跑完按设定间隔自动进入下一轮，可设每日操作总量上限，达到即停
3. **回关率统计与自动止损** — 关注后满 N 小时自动核验对方是否回关，按来源统计回关率；样本达标且回关率低于阈值时，自动停止该来源

**任务多选 · 自动找目标（v2.1）**
4. **任务类型多选** — 「清理单向关注」和「自动关注目标」可任意组合，一次跑完
5. **关注目标来源多选** — ①我的粉丝列表（回粉）②关键词搜索陌生人 ③指定 UP 的粉丝
6. **关键词搜索自动找人** — 填关键词即可按页搜索陌生人并关注，支持粉丝数上限、最低等级筛选；已自动排除你自己的粉丝
7. **自动关注 × 回粉分流** — 搜索 / 指定UP 只关注「没关注过你的陌生人」，已是你的粉丝一律跳过；回粉统一走「我的粉丝列表」

**稳定性（v2.1.2–2.1.3）**
8. **异常后自动重启** — 任务抛异常后等待设定分钟数自动重启，连续异常达 6 次上限后停止，防死循环
9. **启动时自动恢复任务** — 全局开关打开后，软件每次启动自动接回「有任务且未禁用」的账号，过夜 / 崩溃重启无需手动点开始
10. **看门狗停滞检测** — 单次请求 30 秒超时 + 单轮内连续 N 分钟无进展即判定卡死，强制重启恢复（沉默的挂起也能被救回）

**支持**
11. **联系合作 / 随缘打赏支持** — 顶栏「联系合作 / 打赏」按钮，内含抖音、B站联系方式与微信 / 支付宝打赏码
12. **中文应用菜单** — 文件（重新加载 / 导出 CSV / 数据目录 / 退出）、编辑（撤销重做 / 剪切复制粘贴）、视图（开发者工具 / 缩放 / 全屏）、窗口、帮助（使用说明与风险提示 / 联系合作 / GitHub 主页 / 关于），全中文
13. **关注上限保护** — B站普通账号关注上限 5000。关注数达到设定值（默认 5000，大会员可调高）时自动跳过「自动关注」阶段，改为提示先「清理单向关注」腾名额，避免硬闯被平台拒绝

**满关自救与热更新（v2.1.7）**
14. **满关自救** — 账号配置新增开关：关注数达到「上限 − 预留名额」（默认距 5000 还剩 100）时，①「自动关注」暂停，不再撞上限被拒 ②「清理单向关注」忽略「关注满 N 天」门槛立即腾名额——满员账号每天都能清，不会一直卡在上限
15. **应用内热更新** — 启动 6 秒后静默检查 GitHub Releases，发现新版自动弹窗（版本号 + 更新说明 + 下载进度）；点「立即更新并重启」即下载新版便携 EXE、退出时自动替换并重启。也可随时从菜单「帮助 → 检查更新…」手动触发；「稍后再说」的版本不再自动提醒

## 安装使用

> 当前产物在 **`dist/`**（v2.1.7）

方式一：安装版 —— `dist\B站关注管理台-2.1.7.exe`（NSIS，可选安装路径，建桌面/开始菜单快捷方式）
方式二：便携版 —— `dist\B站关注管理台-2.1.7-便携版.exe`（单文件约 96MB，双击即用，免安装）
方式三：免打包 —— `dist\win-unpacked\B站关注管理台.exe`（解压版，便于排查）

已验证：打包后的 EXE 执行 `--selftest` 通过，结果写入 `%APPDATA%\bili-relation-manager\selftest.txt`。

## 操作步骤

1. 运行 EXE → 点右上角「**+ 扫码登录账号**」，手机扫码登录。
2. 如需第二个账号：关闭登录窗口 → 再次点「扫码登录」，重复即可。**账号数量不限**。
3. 左侧选中账号 → 中间面板配置：
   - 任务类型（可多选）：`清理单向关注` / `自动关注目标`
   - 关注来源（可多选）：`我的粉丝列表`（回粉）/ `关键词搜索`（自动找陌生人）/ `指定 UP 的粉丝`
   - 选「关键词搜索」时填关键词（空格/逗号分隔）；选「指定 UP」时填目标 UID
   - 操作间隔：建议 3000~6000 ms；每轮上限：建议 30~50
   - **演练模式**：默认勾选，只列名单不发写请求。确认无误后取消勾选才真正执行。
   - 勾选「仅处理关注满 N 天仍未回关的」→ 只清理关注时间达到天数的账号
   - 勾选「满关自救」→ 关注数达到「上限 − 预留名额」时：自动关注暂停、清理忽略天数门槛立即腾名额，满员账号每天都能清（上限值见全局设置「关注上限保护」）
   - 勾选「自动循环」→ 设定每轮间隔（分钟）与每日上限（0 = 不限）
   - 「异常后自动重启」「看门狗停滞阈值」→ 无人值守自愈，详见上文
4. 点「全部开始」—— 所有账号各自起一条流水线，**真正并行**，互不阻塞。
5. 右侧三个标签页：
   - **日志**：实时滚动
   - **操作明细**：每条处理结果与跳过原因
   - **统计**：关注/粉丝数、今日操作量、按来源 UP 的回关率与启停状态
6. 全局设置里可维护「不再关注名单」，以及回关率下限、最小样本量、核验延迟、统计刷新间隔。

## 发布新版本（触发应用内热更新）

1. 改 `package.json` 的 `version` 与 `main.js` 的 `BUILD_TAG`，跑测试 + `npm run build`
2. 打 tag 并创建 Release，把两个 EXE 作为资产上传（**必须带「便携版」资产**，热更新优先下载它）：

```bash
git tag v2.1.7 && git push origin v2.1.7
gh release create v2.1.7 \
  "dist/B站关注管理台-2.1.7-便携版.exe" \
  "dist/B站关注管理台-2.1.7.exe" \
  --title "v2.1.7 满关自救 + 应用内热更新" --notes "更新说明…"
```

3. 用户端：启动 6 秒后自动检查，发现新版即弹窗；点「立即更新并重启」自动完成替换。也可菜单「帮助 → 检查更新…」手动触发

## 接口说明

- 列表：`GET /x/relation/followings`、`/x/relation/followers`（需 WBI 签名）
- 变更：`POST /x/relation/modify`，`fid` + `act`（1 关注 / 2 取关 / 5 拉黑 / 6 解除拉黑 / 7 移除粉丝）+ `re_src=11` + `csrf=bili_jct`
- 关系位掩码 `attribute`：`2`=我关注了TA，`4`=TA关注了我，`6`=互粉，`128`=拉黑
  - 清理单向：`!(attr & 4)`
  - 回粉：`!(attr & 2)`

## 安全设计

- `nodeIntegration: false` + `contextIsolation: true`，渲染层拿不到 Node
- IPC 全部白名单注册，入参在主进程校验与转字符串
- 账号凭证仅保存在本机 `%APPDATA%\bili-relation-manager\data.json`，不外传
- 默认「演练模式」开启；`-509` 限流自动暂停；`-352` / `-111` 致命码终止该账号任务
- 支持「特别关注」跳过、认证账号跳过、全局白名单 UID

## 风险提示

批量操作属自动化行为，可能被平台识别。务必：单次 ≤ 50、间隔 ≥ 3 秒；出现 `-509`（频繁）或 `-352`（风控）立即停止并等待数小时。合规使用。
